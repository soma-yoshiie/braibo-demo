# BRAIBO UI ビジュアル案モックアップ — 共通ブリーフ

BRAIBO（ブレイボ, Brain × Ball）は 5 対 5 の「サッカー × 将棋」同時行動タクティクスゲーム（スマホ縦持ち）。
現在の実装は機能するが見た目が「自作ゲーム」風。商用スマホゲームとして通用するビジュアルの方向性を
複数案つくり、PDF の提案資料に載せる。あなたはそのうち 1 案の **静止画モックアップ 2 画面** を作る。

## 成果物
- `screen1.html` と `screen2.html`（それぞれ単独で開ける 1 ファイル。HTML + CSS + インライン SVG のみ。JS 不要）
- `screen1.png` と `screen2.png`（下記スクリプトで撮影、780×1688px）
- 外部リソースは Google Fonts の `<link>` のみ可（fonts.googleapis.com / fonts.gstatic.com は到達可能）。画像ファイル・絵文字は使わない。
- `html, body { margin:0; width:390px; height:844px; overflow:hidden; }`。スクロールなし、はみ出しなし。

撮影: `node /home/user/braibo/concept/src/shot.cjs screen1.html screen1.png`
（出力の `sw`/`sh` が 390/844 を超えていたらはみ出している。`fonts` に指定フォントが入っていること、`errors` が空であることを確認）

## 画面 1: 作戦フェーズ（選手を 1 人選択中）
盤面は **横 7 列 × 縦 10 行** のマス目のサッカーピッチ。青チームが下から上へ攻める。上下のエンドライン中央（列 2〜4）にゴール。
ハーフウェーライン、センターサークル、ペナルティエリア風の線を入れる。座標は (x: 0..6 左→右, y: 0..9 上→下)。

必ず描く要素:
1. 選択中の青 WG #7 の強調と、その **移動可能マス** のハイライト: (5,3) (5,2) (6,3) (6,4) (6,5) (4,4) (4,3)※ (5,5)。※(4,3) は敵がいるマス。
2. 青 ST #9 の移動予定: (3,2) → (4,1) の矢印と移動先のゴースト。
3. **予定パス**: WG (5,4) から ST の移動先 (4,1) への浮き玉パス（弧を描く線）と成功率ラベル「72%」。
4. **オフサイドライン**: 赤 DF のいる y=1 の行の下端あたりに横線＋小さなラベル。
5. 上部 HUD: スコア「蒼嵐 1 – 0 紅蓮」、ターン「7 / 20」、作戦タイマー残り 42 秒（60 秒中）。メニューボタン。
6. 下部: 選択中の選手カード（ウイング / #7 / スキル「パスマスター」/ 主要ステータス: パス 75・クロス 85・フィジカル 40・シュート 55）、
   行動ボタン（移動・パス・クロス・シュート・キープ のうち案に合う見せ方で）、主ボタン「実行」（指示済み 3/5 が分かる表示）。
7. ピッチは画面の主役。マスは正方形に近く（1 マス約 44〜50px）、トークンはタップしやすい大きさ（直径 36px 以上）。

## 画面 2: 見せ場 —「競り合い（DUEL）」のカットイン
青 ST #9（フィジカル 55）がボールを持って赤 DF #4（フィジカル 90）のいるマスへ突っ込み、競り合いが発生した瞬間の演出画面。
- 背景は画面 1 と同じピッチを暗く／ぼかして敷く。
- 両者の対決表示（勝率 **青 38% vs 赤 62%**）、大きな見出し（DUEL / 競り合い）、結果表示（青の勝ち＝番狂わせ「WIN」）。
- 「ボールキープ成功」など結果 1 行。案の世界観を最も強く見せる画面にする。

## 品質基準（最重要）
- **App Store に載っている商用スマホゲームのスクリーンショット** に見えること。プロトタイプ・管理画面・Bootstrap 風に見えたら失敗。
- 文字: 既定フォント禁止。指定フォントで階層（特大数字／見出し／ラベル／補足）をはっきり付ける。字間・行間を整える。
- 奥行き: 影・ハイライト・グラデーション・ぼかし・テクスチャを使い、平板な単色ベタ塗りの円＋文字にしない。
- 整列: グリッドに正確に乗せる。要素同士の重なり・文字の切れ・はみ出しゼロ。
- 一貫性: 色・角の処理・線の太さ・影の方向を案のルールで統一する。
- 余白と密度: HUD は必要最小限、ピッチを広く。下部カードは情報を整理して詰め込みすぎない。
- 日本語テキストは自然な表現で。

## 進め方
1. まず画面 1 を作り、撮影した PNG を **自分で開いて見て**（Read ツールで画像を見られる）、
   デザイナーとして厳しく批評し、修正する。これを **最低 3 回** 繰り返す（配置ずれ、文字の重なり、安っぽさ、コントラスト不足を重点的に）。
2. 画面 2 も同様に最低 3 回。
3. 2 画面でスタイルが揃っているか確認。
4. 作業フォルダ以外のファイルは変更しない。コミットしない。
